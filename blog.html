Build notes

I built a daily options-flow scanner for stocks nobody else covers

July 2026 · ~5 min read

Most "unusual options activity" tools I could find were all built around the same 50–100 mega-cap tickers — SPY, QQQ, NVDA, TSLA, the usual suspects. Which makes sense, that's where the volume and the ad dollars are. But it also means the Russell 2000 — about 2,000 small-cap stocks — is basically a blind spot. Less liquid names, so when unusual volume does show up there, it tends to be a much more lopsided, easier-to-spot signal than in a name that trades 50 million shares a day.

So I built a scanner that only looks at that blind spot.

What it actually does

Every trading day, a script:

  • Pulls the current Russell 2000 constituent list (from iShares' public holdings CSV — this alone took longer to get right than I expected, since their endpoint occasionally blocks requests from cloud IPs)
  • For each ticker, grabs the near-term options chain and totals call/put volume and open interest across the closest couple of expirations
  • Flags anything where volume is unusually high relative to open interest, or relative to that ticker's own recent average once enough history has accumulated
  • Finds the specific strike + expiration where the flow is concentrated, not just "calls are busy" but exactly where
  • Sends the results to a Telegram channel

That's it. No ML, no "AI-powered predictions," just volume math run against ~2,000 tickers once a day.

The parts that were more annoying than the "hard" part

The actual signal logic was the easy part. What ate most of my time:

  • Data source reliability. I'm using yfinance, which is an unofficial wrapper around Yahoo Finance. It works, but it's not built for scanning 2,000 tickers daily without hitting rate limits, so the whole thing runs through a thread pool with deliberate delays.
  • Where "today" actually starts. Building a meaningful "volume vs. 20-day average" metric means you need to have been tracking a ticker for 20 days first. Day one, that number is meaningless. It only gets useful once the history accumulates — which is obvious in hindsight, less obvious when you're staring at your first day's empty comparison column.
  • Scheduling reliability. I run this on GitHub Actions' free tier with a cron trigger. Learned the hard way that scheduling a workflow for the top of the hour (e.g. 13:00 UTC exactly) means it competes with every other cron job on the platform doing the same thing, and can get delayed by hours during high load. Moving it to an odd minute (12:37 instead of 13:00) fixed it.
  • Timezone math with two clocks that don't agree. US market hours run on a clock that shifts twice a year (DST). My own timezone doesn't. Cron only understands UTC. Getting "30 minutes before market open, in my own local time, year-round" to actually mean what I wanted took more napkin math than I'll admit to.

What I'd do differently

If I were starting over, I'd pay for a real options data feed (Polygon, Tradier) from day one instead of routing everything through an unofficial scraper. It would have saved a lot of the rate-limit and reliability headaches. I stuck with the free approach mostly because I wanted to see how far a zero-budget version could get before I spent anything — turns out, pretty far, but not without some duct tape.

Where it stands now

It runs daily, unattended, and has been catching some genuinely interesting setups in names I'd never have looked at otherwise. I've since wrapped it into a small subscription product, but the interesting part to me was always the scanning problem itself — happy to go into more detail on any of the data/infra pieces if useful to anyone building something similar.
